# 面试问答、源码追问与进阶练习

阅读方法：先遮住参考回答自己讲一分钟，再回到源码找依据。每个问题都要区分概念、项目实现和未完成事项。不要把参考文字逐句背成口号。

## 一、怎样介绍这个项目

### 1. 一分钟项目介绍

“我做的是桂林共享站物资服务系统。居民提交辖区、物资类型和数量，工作人员查询并分配同辖区有效库存。它是 Spring Boot 模块化单体，MySQL 保存求助、库存批次、分配明细和 Outbox；Redis 用于站点缓存、限流和短租约；RabbitMQ 负责分配通知事件。创建请求用数据库用户加幂等键唯一约束，分配先锁求助行再锁库存批次，业务变更与 Outbox 同事务提交。前端直接由 Java 应用托管，居民可跨设备查看自己的请求。当前通知是日志模拟，部分分配补单、完整账号治理和大规模性能验证还没有完成。”

为什么这样讲：先讲业务，再讲最关键的不变量，最后诚实交代边界。不要把介绍变成十几个框架名串联。

### 2. 这个项目的难点是什么？

不是写增删改查，而是同时处理重试、并发、权限和跨系统失败。一次请求可能已经提交但响应丢失；两名工作人员可能同时处理同一单；登录用户可能尝试读其他用户的编号；MQ 可能接收成功但应用来不及标记。

回答要指向具体修复：持久化幂等、锁顺序、对象权限、Outbox 和 broker 确认。每个修复各管一个问题，不能用“加 Redis 锁”概括全部。

### 3. 为什么不是微服务？

当前需要一个清晰的库存事务和低部署成本。单体已经能验证并发与跨组件一致性问题。拆服务的收益需要来自团队边界、独立扩容或发布频率，而不是技术展示。

追问“以后怎么拆”：可以按求助、库存、通知职责拆，但先定义数据所有权和事件契约，再考虑跨服务补偿。

## 二、Java 基础与 JVM

### 4. == 和 equals 区别是什么？

基本类型 == 比较值，对象 == 比较引用身份；equals 由类定义逻辑相等。String.equals 比内容，普通 Object 默认相当于引用比较。比较包装类型要注意拆箱和 null，不要依赖小整数缓存造成的偶然 == 成功。

源码练习：找出请求正文比较中字符串与枚举分别如何比较，并解释为什么枚举可以用 !=。

### 5. record 是否完全不可变？

字段引用不可重新赋值，但字段指向的对象可能可变。List 字段需要防御性复制才能避免外部修改。record 适合值型 DTO，但不应直接取代所有 Entity。

项目中的 CreateCommand 和 RequestView 主要包含字符串、数字、枚举和 Instant，比较适合 record。

### 6. HashMap 为什么不能用来保护多线程库存？

HashMap 不是并发库存存储，也不能跨进程共享事务。不仅容器修改有竞争，先读再写的业务复合动作也可能冲突。ConcurrentHashMap 只解决一部分单进程并发访问，仍不能替代数据库事务。

### 7. 泛型擦除有哪些后果？

编译期提供类型约束，但运行时无法直接靠 T 创建对象或识别 List<T> 所有元素的具体类型。反射可以读取部分声明签名，不能把“擦除”误讲成“所有泛型元数据都不存在”。

### 8. checked exception 会影响事务吗？

默认 Spring 事务通常对 RuntimeException 和 Error 回滚，checked exception 需要明确 rollbackFor 等策略。实际还取决于配置和异常是否传播出代理边界。捕获异常后返回成功，会让外层可能正常提交。

### 9. OutOfMemoryError 与内存泄漏一样吗？

不一样。有效业务负载过大、配置过小也能 OOM；泄漏是生命周期结束的对象仍被引用，持续积累。诊断看对象保留链、增长趋势、请求量与堆预算，而不只看一个异常名。

### 10. 怎么排查接口偶发十秒响应？

先定位耗时在哪一层：网络、连接池等待、SQL、锁等待、MQ confirm、GC、CPU。用 Trace ID、线程栈、慢 SQL 和指标关联。不能在没有证据时直接更换 GC 或增大线程池。

### 11. 虚拟线程为什么不会让数据库无限并发？

虚拟线程降低等待时线程资源开销，不增加 MySQL 能力，也不增加 Hikari 连接数。下游容量仍是硬边界，必须限流和背压。CPU 密集计算也不会凭虚拟线程变快。

### 12. ThreadLocal 为什么要清理？

线程可能被复用，旧值会跨任务残留；值还可能长期持有对象。MDC 的清理放 finally 是同类思路。异步切换线程后，上下文也不会总是自动正确传播。

## 三、Spring 与接口层

### 13. 单例 Service 为什么通常能并发使用？

前提是它只保存稳定依赖，把请求特有状态放在局部变量中。单例本身不保证安全。如果 Service 存 currentUser、requestNo 等可变字段，多个请求可能互相覆盖。

### 14. 构造器注入比字段注入好在哪里？

依赖在构造时明确，方便 final、单元测试和缺依赖时快速失败。它不是装饰性风格选择，而是让类在没有 Spring 上下文时仍然可构造和测试。

### 15. 事务自调用失效是什么意思？

代理只能拦截经过代理的调用。同一个对象内部 this.xxx 不会再次穿过代理，因此内部方法的事务注解不能凭空创建新边界。若外层已经有事务，内部代码仍运行在那个事务中，不是“代码完全没事务”。

### 16. Controller 为什么不能直接返回 Entity？

可能暴露内部字段、触发懒加载、产生循环引用，并让 API 跟数据库结构强耦合。DTO 明确公开范围和格式。新建输入更不能直接接受 Entity，否则用户可尝试修改 requesterId 或 status。

### 17. 为什么认证错误不全在 Advice 中处理？

Security 过滤器可能在进入 DispatcherServlet 前就拒绝请求。MVC 的异常处理器不是所有 Servlet 阶段的全局 catch。当前 SecurityConfig 提供 401/403 JSON 处理，MVC Advice 处理控制器侧错误。

### 18. 为什么 PageImpl 改成自定义 PageView？

内部框架对象的序列化结构不应成为长期 API 契约。PageView 只公开 content、number、size、totalElements、totalPages，降低框架升级对前端的影响。

### 19. 400、401、403、404、409 怎么区分？

400 是请求不合法；401 是没有有效身份；403 是有身份但无操作权限；404 是记录不存在或当前身份不可见；409 是业务状态冲突。居民查他人的记录用 404，避免泄露目标是否存在。

### 20. 为什么要固定分页排序？

创建时间可能相同，单按时间排序没有稳定的第二排序键。加 id 使顺序确定。即便排序稳定，在并发插入下 offset 分页仍可能跨页移动，要求更强连续性时可用游标。

## 四、MySQL、事务与并发库存

### 21. 联合索引“最左前缀”如何联系项目？

(requester_id,created_at,id) 支持先按居民缩小范围，再按时间和 ID 检索。缺少前导条件时不能机械期望相同效率；优化器也可能选择其他访问方式。最终看数据分布和执行计划，不只背口诀。

### 22. 为什么包含 LIKE 可能慢？

%keyword% 一般无法像前缀模式一样用 B+Tree 定位连续范围；即使用其他条件索引缩小候选范围，仍可能逐条匹配。用户按完整编号查询时可以考虑精确查询接口。

### 23. saveAndFlush 是否等于提交？

不是。flush 让 SQL 尽早发给数据库、暴露约束错误，但事务仍可能回滚。commit 才是提交边界。返回对象已经有 ID，也不意味着事务必然成功。

### 24. 为什么修改托管 Entity 不一定显式 save？

JPA 持久化上下文跟踪对象状态，flush 时对比变化并更新。离开事务、对象脱管后不能仍假定这种行为。理解托管范围才能判断数据是否会保存。

### 25. @Version 的作用是什么？

它在更新中检测并发版本变化，冲突时失败，防止静默覆盖。不是自动解决所有一致性问题；开发者仍要决定是否重试，以及重试后业务判断是否还成立。

### 26. 为什么先锁请求再锁库存？

先串行化同一个请求的分配决策，后来的事务在锁释放后看到新状态，拒绝重复分配；库存锁保护不同请求对同批次的竞争。这两层分别对应两个共享资源。

### 27. 用 Redis 锁替换数据库锁是否更快？

未必。Redis 锁会有租约过期、持有者暂停、主从切换等问题，还需要数据库最终约束。当前所有库存修改在同一个 MySQL 事务内，数据库锁简单直接。吞吐必须实测，不能把网络服务换成 Redis 就称为优化。

### 28. 加锁顺序固定是不是绝对不会死锁？

不是。执行计划、其他业务路径、外键检查和范围访问都可能引入额外锁。固定顺序减少风险，仍应处理死锁和超时，记录失败并有限重试。

### 29. FEFO 为什么特意处理 NULL？

MySQL 升序对 NULL 的位置可能让无有效期批次排到前面，而业务要求先消耗会过期的物资。查询通过 CASE 把无有效期放最后，并用 id 打破同时间排序。

### 30. 为什么部分分配不能直接再点一次？

当前接口只允许 PENDING。补分配要计算“请求量减已分配量”，处理同请求同批次唯一约束，避免重复通知，定义无库存时保持什么状态。只删掉状态检查可能导致再次按原始数量分配。

### 31. 事务为什么不包含 Redis 原子性？

Spring JPA 事务管理器控制的是数据库连接事务，Redis 调用和 MQ 发送不是自动参与者。若要跨资源一致性，需要协议、补偿或事务消息等设计；不能凭方法上一个 @Transactional 得到分布式原子性。

### 32. 数据库唯一键为什么仍然必要？

并发的先查后插可能都读到不存在。唯一约束在数据库写入点仲裁。应用提前检查负责可读性和快速回放，约束负责最后的竞态防线。

## 五、Redis、幂等与缓存

### 33. 幂等和防重复点击一样吗？

不是。按钮禁用只减少同页面的重复操作；幂等还要覆盖超时重试、多标签页和客户端重放。业务 key 必须跨重试保持稳定，数据库要记录作用域和对应结果。

### 34. Redis 数据丢失后为什么还不会重复建单？

用户加幂等键唯一保存在 MySQL，Controller 在访问 Redis 之前先回放已有记录。新请求仍依赖 Redis 租约可用性；已存在请求回放不需要 Redis 完成标记存在。

### 35. 同 key 不同正文怎么处理？

返回 409。否则用户可能想提交 20 份却收到之前 1 份的回放而不自知。当前比较辖区、类别、数量、紧急程度；未来新增会影响业务的字段，也必须纳入比较或规范化指纹。

### 36. 为什么不能直接 DEL 释放租约？

旧持有者暂停超过 TTL，新持有者已经获得锁时，旧持有者恢复后 DEL 会删别人的租约。随机 owner 加原子 compare-and-delete 才能确认释放的是自己的锁。

### 37. 限流为何用 Lua？

把递增与首次设置 TTL 放在一个原子步骤，避免进程在两条命令间失败留下永久计数 key。Lua 不自动解决业务层所有竞态，只负责脚本中的 Redis 操作原子执行。

### 38. 固定窗口有什么边界问题？

前一窗口末尾和后一窗口开头可以集中通过两倍配额。要平滑可用滑动窗口或令牌桶。方案选择取决于限制“长期平均量”还是“瞬时突发量”。

### 39. 缓存穿透、击穿和雪崩区别？

穿透针对不存在的数据；击穿针对热点 key 过期；雪崩针对大量 key 同时失效或整个缓存不可用。空值、互斥重建、TTL 抖动、限流降级分别适用不同原因。

### 40. “先更新 DB 再删缓存”保证绝对一致吗？

不保证。删除失败和并发回填仍有窗口。需要重试、变更事件或 CDC 等补偿。根据业务选择陈旧容忍度，不应把一个顺序描述当成强一致协议。

## 六、MQ 与可靠消息

### 41. Outbox 解决了哪一步丢消息？

解决业务提交后忘记或来不及记录“需要发消息”的窗口。业务和事件行一起提交，之后能重试发布。它不能自动确保消费者真实业务成功，也不消除重复投递。

### 42. confirm 与 return 区别？

confirm 表达发布端与 broker 间的接收结果；return 表达 mandatory 消息无法路由。可能收到 ack 但消息没有路由到目标队列，因此两者都要处理。当前发布器检查 Future ack 和 returned 状态。

### 43. 为什么还会重复投递？

发送已确认但数据库更新 PUBLISHED 前崩溃，重启后事件仍待发布，必然重发。消费者需要识别相同事件 ID，真实副作用需要业务幂等。

### 44. 先设置消费去重标记有什么风险？

设置标记后、执行副作用前崩溃，下一次可能被当成已完成而跳过。当前消费者只是模拟日志。真正发送短信要有任务状态、供应商幂等键或事务性本地处理，不声称 exactly-once。

### 45. Outbox 批量事务有什么性能代价？

确认等待发生在持锁事务里，网络慢会扩大持锁时间，多实例会竞争。可以分离认领、发送、结果落库，但必须补上认领过期和恢复机制，复杂度随之增加。

### 46. 失败十次之后怎么办？

当前进入 FAILED，需要人工分析原因再设计恢复流程。生产上要有告警、事件重放权限、操作审计与避免再次重复副作用的策略。不能无限快速重试把下游打垮。

## 七、安全、测试与部署

### 47. JWT 放 localStorage 有什么风险？

XSS 可读取它。要避免将接口内容拼成未经转义的 HTML，使用合适 CSP 和依赖治理。HttpOnly Cookie 是另一种方案，但需要配套 CSRF 设计。没有一种存储方式免除所有前端安全责任。

### 48. 角色校验通过为什么还会越权？

角色只证明属于某类用户，不证明拥有某条数据。对象权限必须核对 owner，查询列表也必须带身份范围。用不可预测编号只能降低猜测概率，不能替代授权。

### 49. Token 有效时禁用账号会即时失效吗？

当前不会保证即时失效，Token 校验主要依据签名、角色和到期。若需要立即封禁，可以使用短 TTL、版本号、撤销表或每次读取用户状态，代价是状态依赖与额外查询。

### 50. 当前项目哪些不能说成生产级？

演示 noop 密码、默认密钥、模拟通知、没有部分补分配、没有完整监控告警、Redis/MQ 数据卷不足、缺少自动 Testcontainers 集成套件、未做大规模压测和故障切换。承认边界并说明演进方向，比声称“功能全”更可信。

### 51. 单元测试为什么不能证明行锁？

mock 返回值不会启动 MySQL，也不会真的阻塞另一个事务。锁行为要在真实数据库和事务并发下观察。当前 smoke 并发请求补充这层验证，但规模与故障场景有限。

### 52. 前端为什么要处理响应乱序？

较早查询可能较晚返回，覆盖较新的用户输入结果。版本号只接受最新查询响应；防抖减少请求量，两者作用不同。后端仍要限制参数与权限，不能把安全放到前端。

### 53. 为什么更快的平均响应不等于优化成功？

尾延迟可能恶化，错误率可能提高，系统可能只是在快速失败。一起看 P95/P99、吞吐、成功率、资源消耗和数据正确性。

### 54. Docker Compose 的 localhost 是什么？

应用在宿主时 localhost 指宿主，映射端口可访问容器；应用在容器时 localhost 指自身容器，连接其他服务通常用 mysql、redis 等服务名。很多连接失败是部署拓扑理解错误。

### 55. 怎么处理线上未知 500？

先用 Trace ID 找日志，再确定影响范围与依赖健康；不要立即清缓存、重启所有组件或改数据库。优先收集证据，采取可恢复的缓解，再修复并补回归测试。

## 八、十个可以真正提升能力的源码练习

以下练习尚未全部实现；完成后需要自己的测试证据。

### 练习 A：完整部分补分配

设计 outstanding = requested - sum(allocations.quantity)。同一请求加锁后计算剩余量；同一批次已有明细时选择累计或新的业务唯一键策略。通知中区分本次新增量和累计量。测试首次部分、二次完成、二次无库存、并发补分配。

### 练习 B：取消与库存释放

列出可取消状态，锁请求与相关批次，在同事务减少预留量并记录释放事件。已签收是否可取消需要业务决定。测试两次取消、取消与分配并发、释放后可用量。

### 练习 C：BCrypt 账号迁移

不要改已执行 V1。新迁移或专门受控流程生成 BCrypt hash，保持 DelegatingPasswordEncoder 前缀。用新旧账号登录测试，并确认文档不再推荐明文默认密码。

### 练习 D：Token 撤销

比较黑名单、用户 tokenVersion、短 TTL 加刷新令牌。明确登出、改密、禁用、泄露时的行为。测试撤销传播延迟与 Redis 故障时策略。

### 练习 E：Outbox 短事务认领

增加 claimOwner、claimUntil，短事务认领，事务外发送，再按 owner 确认。考虑工作者暂停、租约过期、重复发送、进程重启。数据库状态机要清楚，不能只给代码加异步。

### 练习 F：可靠通知任务

设计 PENDING/SENDING/SENT/FAILED，供应商请求带稳定幂等键，记录供应商返回 ID。讨论“供应商已送达但我方超时”的未知结果如何查询与对账。

### 练习 G：自动化集成测试

用 Testcontainers 为每次 CI 提供独立 MySQL、Redis、RabbitMQ，执行 Flyway，再跑身份、幂等、并发、消息测试。测试结束自动销毁隔离容器，不依赖开发机已有库存。

### 练习 H：真实库存查询和管理

给管理员提供按站点和类别的库存接口，避免虚构统计。新建批次要验证有效期和数量，操作加入审计。居民看到的库存是否应该精确暴露，先定义产品与安全边界。

### 练习 I：游标分页

以 createdAt 与 id 为游标，保证排序边界一致。测试相同时间、多页、插入新记录和删除记录时的行为。说明不能随意跳第 N 页的产品取舍。

### 练习 J：性能和故障报告

固定数据和负载，测基线；只改一处优化后再测。模拟 Redis 不可用、MQ 不可用、DB 锁等待，写出真实观察，不编造 QPS。报告必须包含环境、参数、错误率和数据正确性检查。

## 九、项目答辩自检

把下面十个问题逐个讲清，再考虑把这个项目写进简历：

1. 为什么这个请求属于当前用户，而不是 body 传来的 userId？
2. 客户端超时之后你如何判断业务有没有发生？
3. 同键换正文为什么不是普通重试？
4. 两个分配同时进来时哪个 SQL 先加锁？
5. 预留与出库的区别在哪里体现？
6. MySQL 成功、Redis 失败后怎么恢复？
7. RabbitMQ ack 到底证明哪一步？
8. 为什么模拟消费者还不能叫可靠短信系统？
9. 你实际运行了哪些测试，哪些没有？
10. 下一步最值得修的限制是什么，代价多少？

简历可以写已实现的权限隔离、幂等回放、事务分配、Outbox 确认和实测结果。不要写“千万级并发”“绝不丢消息”“覆盖全部后端知识”等没有证据的结论。
